# PersonalKB Linux deployment

Unpack the deployment kit on Ubuntu 24.04 x86-64. Install Docker Compose and configure a separate HTTPS vhost using nginx.conf.template; replace all placeholders, including __APP_PORT__ with the port passed to configure.py (default 8768). Existing sites and services must be preserved.

Run `python3 deploy/configure.py --hostname kb.yuanzhll.top --output /absolute/config-dir` and create private state, state/tmp and backup directories. Create a private secret file containing PERSONALKB_PASSWORD_HASH generated with the project password setup tooling; model keys are optional and must never be included in a report. Set STATE_DIR, CONFIG_DIR, SECRET_FILE and BACKUP_DIR in your shell or a private Compose environment file. Run `sh deploy/operate.sh report --config /absolute/config-dir/web.json --state /absolute/state --secret /absolute/secret-file` and address failures. Configure TLS and DNS separately; the report does not verify them.

Run `sh deploy/operate.sh check`, `build`, then `start`. The HTTPS proxy listens on the existing Nginx instance; the application binds loopback only. `stop` affects only these two services. Backups use `backup`; verify/export/retention/push accept the maintenance CLI arguments. See `python tools/maintenance.py --help` for available operations. Backup data and secrets must be stored separately and an external copy maintained. Restore only into an empty directory and verify before replacing a working installation.

Target-machine checks are required for Docker image, HTTPS, resource coexistence, recovery and real model workflows; a local preflight alone does not certify them.

Create the authentication secret on the host from the project root with `python3 -m tools.auth_setup --config "$CONFIG_DIR/auth.json" --output "$SECRET_FILE"`. The command prompts privately and refuses to overwrite an existing file. Add optional model keys separately to the private file. Export the four directory/file variables before running the commands below.

`start` is intended for the first start or after `stop`; its preflight refuses an occupied port, including one held by this service. Use `sh deploy/operate.sh restart` when both services already run. To preserve existing configurations, `configure.py` refuses to overwrite; `--force` explicitly permits replacement.

To import a previously exported migration ZIP, put it under the host BACKUP_DIR and run `sh deploy/operate.sh import --archive /backups/migration.zip --target-empty-dir /state/restored`. The archive is verified and restored into the empty directory; secrets are excluded. To restore a snapshot instead, run `sh deploy/operate.sh restore SNAPSHOT --target-empty-dir /state/restored`. These commands stop and restore only this project's previously running services; they do not replace active state. Stop the services, inspect the restored `workflow` and `budget.sqlite`, and explicitly arrange them at the configured state paths before starting. Rebuild path-dependent indexes explicitly after migration. For OSS, set `storage_mode` and the private bucket settings in maintenance.json, export the two configured credential environment variables, and run `sh deploy/operate.sh push SNAPSHOT` or `pull SNAPSHOT`; pull downloads and verifies a snapshot before a separate restore. Never put credentials in the configuration or deployment bundle.

For daily backups, review `deploy/systemd/personalkb-backup.service.template` and `.timer.template`, replace the project directory, private environment file, and daily OnCalendar time placeholders, then explicitly install and enable the units on the server. The timer uses Persistent=true to run after a missed schedule. `sh deploy/operate.sh daily` stops the project services, creates and verifies a cold snapshot, and pushes it only when maintenance storage_mode is oss. Manual mode asks for an external copy; it does not make a daily full ZIP. The latest status is written to `$STATE_DIR/backup-status.json`. The service restores only project services that were previously running, even after failure. No schedule is installed automatically.

ZIP extraction tools may not restore executable permissions; the `sh deploy/operate.sh` commands above do not depend on the executable bit.
