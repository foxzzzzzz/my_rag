# PersonalKB UI评审清单

按本次任务选择相关项。样稿用`docs/ui-design-test-cases.md` U01–U11；正式接入需增加真实接口回归，不重复使用演示通过结论。

| 维度 | 要检查的实际行为 |
|---|---|
| 模板感与用途 | 先判断是否为笔记/资料管理工具：没有无用英文眉题/标语/英雄标题；列表密度合理，文案说明动作；不要用换色或另一套海报/报纸模板冒充重新设计 |
| 信息层级 | 5秒能看出页面用途、当前资料/范围、主动作；不靠大面积空白凑布局 |
| 中文阅读 | 长标题、自然段、数字单位、表格/代码可读；正文行宽、字号和段距舒适 |
| 来源证据 | 视频时间/画面与HTML原文入口不同；①能找到对应证据，内部ID折叠；不存在无效定位的承诺 |
| 状态诚实 | 待审、已批准、修改后待审、索引状态彼此区别；演示数据与真实结果区分 |
| 动作边界 | 分数不自动批准；重处理说明付费；撤回/删除/重传不绕开版本语义；无答案不给无关引用 |
| 审核连续性 | 切证据/导航返回保留评分和意见；保存后改动有未保存提示；门槛附近97/98分与未保存改分不能误批准；批准记录能查看意见 |
| 视觉一致性 | tokens、图标、控件高度、主次/危险按钮、状态颜色和选中态跨页一致；小字号正文/辅助信息与背景对比度目标至少4.5:1，付费/错误说明不能只做很浅的小字 |
| 样稿到正式还原 | 同浏览器/同页/同尺寸/对应状态截图并列；测量字号、品牌/图标、顶栏/侧栏/主区对齐、上置筛选、状态日期列、标签/审核分隔及问答宽度；真实业务差异单列，不以功能测试/灰白配色代替还原 |
| 桌面/手机 | 桌面与390px小屏都能完成关键操作；无整页横向溢出；移动端审核不丢失 |
| 键盘/可访问性 | 字段有label、按钮有名称、焦点可见；弹层Esc关闭并归还焦点；状态不只靠颜色表达 |
| 空/错/忙 | 样稿至少有无结果/拒答；生产必须覆盖加载、空库、失败/重试、过期/冲突、权限与中断状态 |
| 真实边界 | 检查网络/源码是否调用正式API，检查数据与草稿没有被样稿写入；不得用模拟通过宣称真实链路通过 |

问题记录需写触发操作、观察结果、用户影响和优先级；优先修正会导致误审批/误付费/数据丢失的问题，再处理流程阻塞和阅读障碍，最后微调装饰。截图验收写明视口和版本，避免仅用自动规则打分替代人看页面。
