## 实际调整

采用[frontend-design调研与安装记录](ui-skill-research.md)，并修正项目skill。第一版失败的关键不是缺少控件检查，而是用了与日常知识管理无关的展示式视觉惯例；skill增加不能替代设计判断。

| 第一版问题 | 第二版处理 |
|---|---|
| 每页英文眉题、宣传口号 | 从页面内容移除，保留普通中文功能名称 |
| 暖底/墨绿、大标题与宽大展示间距 | 中性灰白工作区、系统无衬线字体、23px标题和紧凑工具条 |
| 资料行高大、浏览密度低 | 压缩为可扫描列表；状态/日期对齐，四份资料在桌面一屏可见 |
| 主题只作为标签展示 | 侧栏和工具条联动过滤，主题从演示资料去重生成 |
| 每份正文重复通用“核对要点” | 删除填充小节，保留原演示正文；核对说明位于审核区 |
| 中等宽度阅读可能受双侧区域挤压 | ≤1050px审核下置，主区筛选转两列；780px补验 |
| 引用/路由辅助语义不足 | ①带展开状态与目标关联，新页标题接收焦点；切证据与弹层返回焦点保留 |

## 独立评审与限制

独立评审对比首版截图，确认三页有实质结构变化；源码覆盖主题状态、98分门槛、未保存变更拦截、草稿/意见与演示隔离。它未亲测浏览器、读屏或真实服务，不把主代理动态证据写成独立实测。

评审建议已落实：去除通用正文填充、问答75ch行宽、≤1050px审核下置、引用展开语义及路由焦点。声明色值静态对比度：辅助文字对白底约6.26:1、侧栏底5.63:1，蓝色操作对白底6.48:1、待审5.97:1；禁用控件的浏览器淡化不计入这些值，不宣称全面无障碍认证。

当前只验证演示流程，尚不覆盖真实加载/失败/版本冲突/撤审失效等；这些仍在3U-C正式接入时验收。演示正文只是布局素材，不作为新提取或新问答质量证据。第一版已被本人否定，第二版也不能因工程检查通过自动视为设计通过。
