# 视频模型请求恢复

11 月 14 日手动回补的 7 条视频均已下载并入库，5 条完成转换。《为什么有了 MCP，还需要 Skill？》在北京时间 12:41 停于 DeepSeek 生成文本，已完成转写和 20 帧分析，该步骤本地预留 ¥0.75。《AI 接管微信开发者工具，自动测试小程序》在 12:47 停于 Qwen 视觉分析帧索引 2，已完成转写和前 2 帧，该步骤本地预留 ¥0.10。

两条的阶段均为 `in_flight`，没有保存供应商请求号、响应或用量。原客户端把 HTTP、连接和超时错误统一归类，转换任务也只记录通用失败。模型调用前先写费用预留再标记发送中，这两条记录无法证明请求到达，也无法据此核对实际扣费。所用 Chat Completions 接口未提供可通过本地任务 ID 获取原响应的方式。

在「任务 → 处理模型请求」可使用校验通过的本地已保存响应，或确认追加额度后重试中断步骤。复用该任务原文件、媒体缓存、转写和已完成的视觉分析。每次重试独立预留并纳入累计预算，原预留保留。后续未执行的步骤继续使用原处理额度，生成资料仍进入待审核。

`config/video-pipeline.json` 的 `chat_timeout_retries` 默认是 1，按视觉帧或生成文本步骤分别计数。设为 0 可关闭。运行中的模型请求明确超时后，在当次执行中自动重试，逐次保留费用预留，受收藏单条、任务和累计预算约束。自动次数用完后，或遇到只有结果未知记录的旧任务，进入 Web 恢复流程。一次手动确认只授权一次该步骤的重试。

| 用例 | 预期 |
|---|---|
| VR01 | 收到响应后、阶段提交前中断，使用已保存响应继续，原步骤和 ASR 各执行一次。 |
| VR02 | 缺少响应时，未确认费用、报价不匹配或重复提交均不会再次发起模型请求。 |
| VR03 | 重试后仍未收到响应，下一次需要新的明确同意和独立预留。已完成步骤继续复用。 |
| VR04 | 原媒体缓存缺失时返回明确错误。未核准费用的供应商调用保持拦截。 |
| VR05 | 视觉或文本请求明确超时时默认各重试一次。设为 0、额度不足或出现其他异常时不会自动重试。重启后已发出的未知请求不会重复发送。 |
| VR06 | 分别用空输出、长度截断和缺少内容字段的响应验证错误码。任务详情显示结束原因、输出字符数及 Token 用量，缺失字段显示「未记录」，零值正常显示。旧合并错误仍可打开恢复入口。 |
| VR07 | 新视觉请求发送 3,072 输出 Token 上限并通过每帧 ¥0.10 的预算校验。按旧上限开始的任务续跑时复用媒体清单和转写结果，未完成帧使用新上限。 |

11 月 14 日视觉帧 2 的两次手动重试结束于 14:20 和 15:07。百炼审计日志按请求号匹配到两次 HTTP 200，均记录 2,146 输入、1,536 输出、3,682 合计 Token。输出用量两次均达到生产上限 1,536，支持截断判断。控制台推理日志未开启，应用历史记录也缺少原始结束原因，无法直接确认历史 `finish_reason`。

部署时同步挂载配置中的 `demo-run.json` 的 `vision_max_tokens` 和 `video-pipeline.json` 的 `legacy_vision_max_tokens`。前者决定新视觉请求的输出上限，后者用于核验已按旧上限开始的任务和媒体清单。新上限 3,072 在当前公式下的单帧保守费用为 ¥0.096256，单帧预留仍为 ¥0.10。
