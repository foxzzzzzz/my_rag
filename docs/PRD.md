# PersonalKB 产品规格

## 1. 定位与成功标准

为单个用户建设以 Obsidian Markdown 为长期载体的云端个人知识库。将有权处理的抖音视频、本地视频和 AI 输出 HTML 整理成带原始证据、可分类、可问答、可导出的知识。先验证音画联合提取，再验证检索，最后开发业务系统。本文定义完整首版需求，不表示技术候选已通过验证。

成功标准：方便导入；每份内容由本人查看真实转换结果、百分比评分并明确批准后正式入库；默认主观质量目标98分（0–100）。分数是个人评估，不是基于标注集测出的统计准确率。引用可定位，并满足预研调用额度及资源约束，日常月费只观察和列优化待办。逐事实标注、50视频/500事实、60+20问题及客观Recall不再作为当前强制前置条件，保留为以后需要时启用的专项基准。

## 2. 已确认需求与边界

2026-11-10：其他客户端提交新审核后，即使资料版本和资格未变，已打开的问答页也会在下一次成功的资料轮询后撤下旧结果，保留问题并提示重新提问。返回问答和读取引用时继续重验。

2026-11-06本人已确认第二版方向，进入[3U-C正式接入约定](phase-3u-frontend-contract.md)。评分草稿保存只在当前页面会话内，按来源/版本隔离，刷新会丢失；不是正式审核。明确保存后再提交批准/返工/拒绝，保存后修改须重存，后台新版本不继承旧草稿。资料库/详情/问答及辅助功能统一使用确认设计，保持真实状态、费用许可和安全文档阅读。工程验收后仍需3U-D本人界面验收。

详情的「← 返回资料库」与标题左对齐，返回时恢复筛选和列表位置。摘要与笔记共用随视口适配的阅读行宽及间距，支持 Markdown 粗体。历史摘要的明确枚举可按列表展示，原字句、数据及取证边界保留。新生成摘要先概括主题，多个明确结论使用 Markdown 项目列表，材料有限定说明时单独成段。已绑定旧摘要提示的任务在完整策略指纹匹配时使用旧提示恢复。视频原片和关键帧位于「画面证据」页签，切换到其他页签会暂停播放。标题右侧的「资料管理」集中下载、分类、Obsidian、人工修订、网页重新整理、版本信息和删除。切换阅读页签或折叠管理区保留当前修订草稿，删除继续二次确认。

资料库固定标题、页面操作及筛选区，包括展开的标签筛选。批量操作栏与资料列表在下方独立滚动。任务页固定标题、归档切换和适用的处理设置，任务列表独立滚动。操作区最多占页面可用高度的 60%，短屏时内部滚动，确保下方列表可访问。点击侧栏「主题」清空全部筛选和勾选，从列表顶部显示全部资料。详情返回保留筛选和浏览位置。全选作用于当前匹配的资料，所选资料可从列表顶部执行批量分类。删除从单份资料详情进入。应用侧栏展示连接状态及退出登录，资料列表定时更新，连接失败时可重试。

存在未删除且没有主题的资料时，侧栏主题首项显示「未分类」。该筛选与搜索、类型、审核和标签筛选叠加。最后一份资料补齐主题后隐藏入口，只解除「未分类」筛选。已有标签的历史无主题资料仍可查找，原标签保留。保存分类时，有标签的资料至少需要一个主题，已有主题满足规则。单份编辑、批量分类、AI 分类建议和 Obsidian 导入共用写入校验，批量按资料逐条报告结果。

当前设计修订以[第二版简报](ui-redesign-v2-brief.md)为准：本人认为第一版模板感过重，暖底/墨绿提案未批准。改为面向日常笔记与资料管理的中性操作界面，去除宣传口号、装饰性英文眉题和展示式大留白；仍保留审核、来源与付费边界。外部skill选择见[调研记录](ui-skill-research.md)。

Phase 4前执行[Phase 3U设计简报](ui-design-brief.md)：资料库以查找/浏览为主，详情把正文阅读、证据和审核分区，问答首屏突出输入及范围、正文自然分段与①来源证据。统一排版、间距、颜色、控件等级、状态与桌面/移动交互。采用项目[UI设计与评审skill](../skills/personalkb-ui-design/SKILL.md)。

先交付独立交互样稿供本人确认视觉方向、三页布局和审核/引用流程；演示数据不调用业务API、不写入真实审核/草稿、不产生模型费用。本人确认后再统一实施生产界面并验收，之后进入Phase 4。保持现有数据/API/模型/存储与审核规则，本轮不新增登录/部署功能。实际付费操作的明确同意、版本失效与权限边界不得因UI简化而删除。

### 3.1 视频与链接

2026-11-05用户明确选择“采用插件策略，修改原有字段规则”。默认download_policy=authorized_playback：用户确认有权处理后，可从已成功取得的目标详情中选择平台返回的播放媒体地址尝试受控保存；allow_download/prevent_download_type/prevent_download不再单独作为禁止条件。strict模式保留旧下载标志检查，供显式配置选择。本次决定覆盖此前仅因这些标志就终止下载的产品规则，不解除登录、付费、验证码及实际HTTP拒绝，也不授权破解、重签媒体地址或更换出口规避拒绝。保存仍需统一素材校验/去重，模型处理须另行同意。

提交 → 去重和媒体校验/链接预检 → 用户确认处理 → 排队 → 带时间 ASR + 抽帧/OCR/视觉理解 → 音画证据融合 → 来源笔记与摘要草稿 → 本人查看、评分并批准 → 正式 Markdown 与索引。HTML等内容也须走本人评分审核。

视频复核页应能播放时间片、看关键帧、编辑转录和知识点及分类；突出数字、单位、术语、音画冲突及材料缺失。草稿、失败、待补件均不能默认参与正式问答。机器原始输出保留，人工修改形成独立版本。

预研先展示每种候选方案的转录、带时间的画面文字/描述、摘要与来源笔记，同时展示方案版本、耗时及费用（未知则明确未知）。本人只需给一个整体分数和一个决定（批准/返工/拒绝），问题标签及备注可选；不用先制作标准答案。默认分数≥98且明确批准才满足审核条件；达标不自动入库。低分返工，高分但拒绝也不入库。当前预研工具只输出审核就绪状态，不执行实际RAG写入。

评分绑定来源哈希、run_id、方案版本及不可变输出版本，修改任一转换结果后必须重新评分；机器原始结果和本人修订结果分开记录。原评分保留，不沿用到新版。若同一版本多次审核，只以最近一次决定为当前状态，拒绝/返工应撤销旧批准资格。

权限不允许或无法取得媒体时不冒充完整处理；用户可上传有权使用的文件。Cookie 不返回前端明文，不进入日志、导出和版本库；云端秘密存储独立设计，不复用 TokBrain 的 Windows DPAPI。

### 3.2 HTML

保留原 HTML，提取标题、正文、表格、链接、图片、公式和可识别的内嵌图表数据。禁止自动执行任意 JavaScript、自动请求外部资源。检测到未提取动态内容时显示缺失及补充入口。原文件只作附件下载，不以内联可执行页面提供；首版不保证还原交互体验。

### 3.3 笔记、版本与问答

每来源一篇完整笔记，包含稳定笔记/来源 ID、来源、时间、主题、标签、处理版本与复核状态。按来源和附件组织目录，分类不依赖目录迁移。重传时按稳定 ID 与基准版本检查冲突，展示差异并由用户选择，禁止直接覆盖并发更新。

问答可限定主题、标签、来源。使用原始证据优先的混合召回，摘要辅助导航；回答引用片段 ID、原文摘录、笔记位置和视频起止时间。资料不足明确说明，删除及更新后旧引用不得作为有效证据。更换 embedding 模型/版本/维度须重建索引并防止混搜。

## 4. 数据与接口原则

Phase 3按[测试用例](phase-3-rag-test-cases.md)及[正式RAG契约](phase-3-rag-contract.md)实施。正式索引只从当前批准且长期内容校验通过的来源取得证据快照，摘要仅导航，研究评分/缓存不可直接授予资格。embedding模型/显式版本/维度/分块配置绑定独立空间，重建原子切换。检索、模型前后及正文发送前重验全部上下文，撤回/修改/删除/文件损坏即时排除；过期引用查询不返回原文。首版回答采用“生成进度事件→完整生成与引用校验→输出回答”的安全事件流，不透传未经校验的上游token；不宣称逐字实时首token流。引用须返回实际证据摘录和可验证定位，HTML为版本证据索引与字符范围，视频为已有时间区间/视觉时间点，不编造DOM或时间信息。

Phase 2D依据[综合用例](phase-2-integration-test-cases.md)和[综合验收补充契约](phase-2-integration-contract.md)实施。AI分类建议只在用户明确同意调用后生成，复用既有文本模型和累计预算，不自动修改分类/审核；建议持久化并绑定正文版本、分类修订号及目录快照，新分类须逐项确认。应用时原子检查并更新，未知模型POST不自动重发。取消/删除立即撤销业务提交资格，但本地正在执行的调用退出前不得释放全局执行占用；进程实际退出后可恢复，不假称已停止远端任务。

Phase 2C2e详情解析默认使用minimal_detail：固定站点详情端点、动态作品ID及外置aid/版本参数，不复制时效签名URL；F2仅显式配置选择，不自动失败切换。单次GET、TLS校验、禁重定向/重试、原始/解压响应双限与父进程总时限保持。strict模式中下载标志明确拒绝优先、未知或非法许可字段不放行；authorized_playback按§3.1用户已确认规则选择实际返回的播放地址，仍保留登录/付费/验证码及HTTP拒绝边界。错误经白名单转为用户提示。该设计不代表所有作品可解析或可下载，D05必须另有当前授权策略下的真实下载/统一导入证据。

Phase 2C2c/d按[分类与往返契约](knowledge-management-contract.md)和[M/O/D编码前用例](phase-2-management-test-cases.md)实施。分类为来源级独立元数据，带稳定ID/别名及并发修订号；不改变正文评分，但同步到当前Markdown。可编辑Obsidian笔记/ZIP经上传预览和显式应用，正文变化生成待审人工版本，分类变化独立处理；上传自报批准无效。抖音链接采用受控下载和私密Cookie配置，缺少真实配置不宣称联调通过。

Phase 2C2a/b 依据[长期内容与HTML接入契约](content-storage-contract.md)和[编码前用例K01–K08/H01–H08](phase-2-content-test-cases.md)。Markdown必须持续落盘，稳定note_id=source_id；永久证据/关键帧与临时处理目录分离。SQLite保留结构化版本、任务与审核，并用持久同步记录处理文件写入失败；未同步或校验失败的内容不得供后续正式检索使用。完整恢复仍需数据库一致性备份，不能只靠Markdown重建审核历史。网页HTML补齐已验证模型整理，区分离线预览与明确同意的付费处理；原HTML不执行脚本，不获取外链，未知POST不自动重复。

HTML 资料详情将离线摘录显示为「正文预览」。正文较长时，在原摘录长度内优先截取到完整句末，找不到句末时沿用原摘录长度，并明确提示省略。与正文完全相同的离线生成笔记默认收起，可从折叠项直达正文。独立笔记、人工修订版笔记和模型笔记各自保留「笔记」页签。人工修订版仍沿用与当前正文匹配的离线摘录时，继续显示「正文预览」。

Phase 2C1按[网页契约](phase-2-web-contract.md)及[编码前用例](phase-2-web-test-cases.md)实现。导入与启动处理分开，视频启动/恢复需明确同意调用；持久派发只处理明确请求，不扫描草稿自动收费。网页复核评分复用当前版本/SHA与98分批准规则，修改产生独立人工版本且重新审核。当前服务默认仅本机开发访问；正式登录/HTTPS和云端部署仍在Phase 4验收。

Phase 2B新增[视频编排契约](phase-2-video-contract.md)及[编码前用例](phase-2-video-test-cases.md)：按输入/模型/参数指纹缓存阶段；付费前沿用累计预算原子预留；ASR有task_id只查询恢复，无ID的未知POST与同步视觉/文本未知POST不自动重发。正式OSS对象归属先于PUT持久登记，清理核实scope且不删除仍被远端使用的对象；临时上传继续由供应商管理有效期。新联网视频命令与2A离线worker分开，产物仍需本人审核。

Phase 2A实施契约见[持久流程契约](phase-2-workflow-contract.md)，编码前用例见[测试用例](phase-2-workflow-test-cases.md)。本轮先交付本地领域服务与CLI：SQLite持久任务、原件去重、租约防重入、不可变产物版本、审核/撤销及Markdown导出；HTML真实安全提取，视频可显式接入原件匹配的已有真实预研结果。自动视频模型编排、Web交互和正式向量索引仍按后续阶段完成，不用测试数据代替本人审核。

知识目录、原文件/证据目录、运行目录分离；索引数据库、缓存和密钥不随 Obsidian 导出。任务持久化，单视频受控执行，记录阶段版本、参数、哈希与可复用缓存。文件与数据库提交失败应能回滚或安全重试。

各能力独立配置 base_url、密钥引用、模型名、超时和能力检查：文本/视觉使用兼容聊天接口，视觉要求图片输入；ASR 适配器统一返回文本及时间段；embedding 使用兼容接口并记录模型、版本、维度。兼容格式不推定全部能力可用。

业务 API 围绕导入任务、来源、复核、笔记、分类、导出与问答设计；具体契约在核心选型通过后冻结。预研工具的输入输出契约见 sample-specification.md，不能视为已经上线的业务 API。

## 5. 质量、费用与资源

### 5.1 质量门槛

以现有sources下3视频+2HTML开始主观评审，无固定样本数或人工gold要求。百分比整体分数关注内容正确、关键信息完整、数字术语和摘要忠实程度。页面应把原始材料和真实输出并列，不能只看流畅摘要或自动生成分数；模型自评不代替本人评分。

先音画提取方案试验，用户认可当前所有demo结果且满足预算/能力条件后再进入检索试验。比较时列出每份材料分数、最低分、未审核项及返工项，不以平均分掩盖低分。最终由本人明确选择主方案及必要备用方案；分数不自动冻结选型，未实测不能冒充已选。

检索通过真实问题、原文和回答出处对照，由本人评价回答质量和是否可用；事实/召回标注集为可选工具。来源失效、缺失或无依据回答须返工，不因主观高分而跳过结构性检查。

上线后每份内容记录处理版本、原始评分、修订评分及问题反馈，按方案汇总低分和常见错误，提示调整ASR/视觉/抽帧/提示词或重新选型。自动优化不得自行切换供应商、花费预算或批量重处理；新版先在现有demo回归，再由本人决定推广。已入库内容发现问题需重新审核，问题版本不继续作为有效检索证据。

如未来启用客观基准，可计算关键事实准确率/覆盖率和Recall；必须单独标为annotated_benchmark，不与personal_review混称。旧离线工具的formal_pass只指专项标注基准，不代表当前工作流批准或入库授权。

### 5.2 费用与运行

每轮调用前记录上界估算，实际用量、重试、缓存均入账；估价未知或可能使总预研支出超过 100 元时不启动新批次。预算不足不得缩小验收集冒充通过，需记录剩余实验及追加成本供用户决策。

完整月费用包括音画、知识提取、分类、embedding、问答和预期重试，按实际使用次数/强度记录和优化；历史100元月目标不再是当前硬验收门槛，相关优化只列Todo，不为降本擅自降低质量。预研累计调用额度仍按上条约束。默认单视频处理，目标整机峰值内存≤3GB；1万知识块本地检索p95≤1秒（不含外部模型），均须目标服务器实测。

成功及失败视频保留 7 天，失败文件清理前提示；Markdown、原 HTML、证据文本、关键帧长期保留。可用磁盘 <8GB 暂停接收新素材。一致性冷备可按频率、时间和时区配置，默认每周日北京时间 03:30 执行，默认保留最近 4 份快照。外部备份目标部署前配置，同盘副本不是灾难恢复保障。

用户删除的资料立即退出资料库、检索和问答，并进入回收站。默认可在 7 天内撤销，恢复原版本和审核记录。到期后随下一次校验成功的定期冷备清理该资料在生产库中的独占数据。仍被其他资料引用的文件继续保留，预算账本和既有备份副本各按原规则保留。升级前已逻辑删除且没有删除时间的资料，从升级迁移开始计算宽限期。

## 6. 安全与工程约束

单用户登录、HTTPS、安全会话、请求校验、限速；上传限制、真实格式、路径和媒体地址验证。独立秘密配置，日志脱敏；样本和标注也可能敏感，默认不入 Git。所有调参、容量、阈值、保留时间在有说明的配置文件管理。

实施前列出测试用例，阶段验收后再推进；遵循上级模型分工与独立审查要求。Git commit/push/Tag 均先确认，禁止 git add -A。本项目不以未经执行的 CI、模拟数据或用户点击确认声称质量通过。
