## 2. 阶段与验收

### Phase 0：规格与测试先行

更新PRD、计划、样本指南和协议；先用 [个人评审测试用例](personal-review-test-cases.md) 定义P01–P10再实施。保留旧工具和历史测试事实；旧formal_pass不是当前批准或入库授权。当前协议见 [个人评审协议](personal-review-contract.md)。

验收：文档统一区分主观评分/客观benchmark、真实/模拟结果、未评分及阶段门槛。文档完成不表示模型预研通过。

### Phase 1A：离线展示与反馈工具

展示真实转换产物：原材料定位信息、转录、带时间的画面文字/描述、摘要、来源笔记、方案版本、耗时、费用，未知项显式标记。源HTML与模型文本转义显示，不执行脚本或自动加载外部资源。

本人每份只填整体百分比分数和approve/rework/reject，问题标签与备注可选。无真实结果时显示待处理，空产物、仅摘要、placeholder或simulation不能获得批准资格。工具只汇总审核就绪状态，不实际写入RAG。

评分绑定来源SHA256、run_id、方案及不可变输出版本；原始机器输出和人工修订分开保存、分别评价。任何内容变化需重新评。同版本最新明确决定生效，后续rework/reject撤销旧approve资格，历史保留。低分不能靠approve越过98分条件，高分仍需明确批准；不以均分掩盖未审核/低分项。

验收：P01–P10相关功能通过，包括非法分数、身份重放、最新决定、安全转义与占位输出限制。合成测试只验证工具，不表示本人已评分、模型质量通过或内容已入库。

### Phase 1B：3视频+2HTML真实转换与本人评审

1. 核对五份源文件身份和处理权限，不要求gold。按能力配置base_url、密钥引用、模型、参数、超时及价格日期。
2. 每批预算预检后做最小能力探测，确认ASR时间戳、图片输入、返回格式、长文件限制与计费。片段探测不冒充完整转换。
3. 预算内逐步比较少量候选，展示完整原始产物，关注音画冲突、数字术语、视觉独有信息、尾部覆盖和HTML结构。候选事实见 [技术预研](technical-research.md)，未实测不锁定。
4. 本人逐份评分并决定；低分/返工分析后生成新版本，旧输出和评分保留，新版本重新审。不由模型自评替代本人判断。

验收：拟推进方案的当前五份demo均有真实完整且可定位结果，逐份≥98分并明确approve，能力与预算条件满足。展示最低分、未评分及返工项；全部获本人认可后才进入检索实测。分数不自动冻结选型，失败留在本阶段，预算不足列明未完成工作。

### Phase 1C：检索与回答试验

只使用1B认可的提取结果。比较标题/时间段分块、2–3 embedding、词法/向量/混合召回；按需要检验重排收益与成本。文档调研可提前，真实检索实验必须等待1B。

本人直接提出真实问题并对照原文和出处，评价回答正确完整程度及可用性。问题数量/gold不强制；需要客观比较时另建专项benchmark。来源失效、无依据回答或错误引用必须返工，主观高分不能豁免结构性检查。

验收：本人认可实际检索与回答效果，引用有效且定位原片段；记录问题、候选、输出版本、反馈和费用。目标机1万块本地p95≤1秒、峰值≤3GB另测；embedding模型/版本/维度更换须独立重建，不混搜。

### Phase 1D：资源验收与本人选型（成本观察）

按每日10视频（平均≤5分钟）+10HTML+10问答×30天测算，包括音画、融合、提取、分类、embedding、问答、重试、双轨和重建摊销；实际用量外推说明样本偏差，不能用低价分项代替完整预算。

验收：预研总额≤100元，能力/资源/引用/评审条件通过，本人明确选择主方案及必要备方案。日常月费按实际次数/强度观察，优化仅列Todo，不作当前阶段硬门槛。记录模型、版本、参数、价格日期、限制和切换策略；不自动切供应商，不静默降质。资源等剩余条件未过仍不进主体业务。

C01和C02已确认，Phase 2已开放；[接入边界A01–A06](production-integration-boundaries.md)留待启用正式私有OSS时验收。
