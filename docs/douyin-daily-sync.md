# 抖音收藏每日同步

## 规则

确认账号后建立最近 100 条收藏视频的基线。少于 100 条时须读到末页，正好读到 100 条时可完成基线。只保存作品 ID、标题及排序，下载和转换均为零。导入页可勾选标题或全选可导入项，确认下载权限及模型费用后整批入队。后台依次下载、入库和转换，生成待审核资料。

手动回补单条费用上限由 `manual_video_budget_cny` 配置，默认 ¥4.05，设为零时暂停接受新的手动付费回补。十条显示合计费用上限 ¥40.50，选择或报价变化后须重新确认。提交时保存每条获同意的上限，执行时逐条预留费用。手动付费回补不占定时下载、转换及日预算，仍受已有视频处理费用限制。旧版已排队的历史回补按原授权只下载。

每日按收藏顺序扫描，只有与上次快照衔接或确认读到末页时才登记新增。只把首个上次已知作品之前的未见作品判作新增。窗口后端补进的旧作品不进入队列。如果完整扫描后没有重叠，重新建立基线并提示，避免把旧收藏误当新增。识别不到账号、分页失败或没有读到边界时暂停派发。账号和队列分开保存，作品在资料库全局去重，包括回收站。只在账号核验通过后处理其队列。

每天默认最多下载 3 条、启动转换 3 条。按排队顺序续跑。自动下载和付费转换由服务器配置控制，自动转换开关默认关闭。已确认每日 ¥12.15、单条预留 ¥4.05，开启后仍受已有模型预算约束。转换生成待审核版本，由用户批准后进入增量索引。

如果旧作品未出现在前 100 条基线或后续扫描中，之后又被重新收藏到顶部，按新出现的收藏处理。作品库仍按 ID 去重。Cookie 更新后可在导入页点「读取收藏」，当天重新核验账号并恢复队列。

## 部署

将 `config/douyin-daily-sync.json` 复制到挂载配置目录，先只打开 `enabled`。新镜像包含 Playwright Chromium，默认使用随镜像安装的浏览器。先在导入页点击「读取收藏」并确认账号。确认基线数量和零派发后，再启用已有抖音下载配置，通过手选少量视频检查导入。

生产调度使用现有 worker，每天在配置的时区和时间首次检查时读取。默认候选为北京时间 05:30，晚于周日 03:30 的备份。启用时设置 `schedule_enabled`，确认自动处理授权后再设置 `auto_download` 和 `conversion_enabled` 及相应的日预算和单条预算。后台按 SQLite 中的日期记录去重，人工点击读取可以立即重试。

## 收藏图文

`mixed_enabled` 默认关闭。开启后，现有账号扫描至少前 100 个混合作品或读到末页，并核对旧视频快照边界。保留原视频基线和队列，窗口内首次读到的图文作为历史条目，迁移不自动下载和转换这些图文。旧视频边界前的新增视频仍按正常规则入队。未找到旧视频边界时暂停迁移。新账号首轮记录最近 100 个混合作品，零下载、零转换。后续以混合快照衔接，只对首个已知作品之前的未见作品自动入队。收藏接口没有可靠的收藏时间，边界之后的未见作品可能是窗口滑入的旧收藏，不能据此触发下载或计费。

图文按图片原顺序下载并逐图校验，保留原文案、作者和来源链接。下载或模型失败时复用已完成步骤。图文转换按图片数报价，逐图视觉请求和一次摘要请求均按配置的 Token 上界、单价及自动重试次数预留。需要手动重试模型请求时单独确认追加金额。图文与视频共用每日 3 个下载名额、3 个转换名额和 ¥12.15 转换预算。手动勾选批次沿用独立额度及报价确认。批准后按文案和图片证据增量索引，图文引用显示图号。

|---|---|

| FS09 | 新账号确认后按收藏顺序登记 100 个混合作品，零下载、零转换。次日新图文进入同一自动队列。 |

### 大图文手动回补

单篇图文最多 40 张。部署时将 `max_images` 和 `manual_work_budgets_cny` 合并到生产挂载的 `douyin-album.json`。后一项按抖音作品 ID 设置手动回补的预算上限。对于 `7707297968927829478`，37 张图的报价为 ¥8.54。WEB 提交时仍须确认本次报价，后台执行时再次核对作品、手动授权和预留记录。定时转换沿用通用单任务预算，累计预算仍约束所有模型调用。

| 用例 | 预期 |
|---|---|
| FS14 | 41 张显示「图片数量超限」，无授权的 37 张显示「单任务预算不足」。指定作品报价 ¥8.54，只有确认当前报价后才入队。 |
| FS15 | 模拟指定作品 37 张全部转换以及每个模型步骤超时重试一次，仍受 ¥8.54 上限约束。缺少手动授权或累计预算不足时零模型调用。定时处理和其他作品继续使用原预算。 |

### 超限图文单篇导入

#### 99 张分批验证

隔离模拟将 99 张分为图 1–40、41–80、81–99。在第 41 和 81 张故意中断后，现有下载检查点复用了已完成图片，最终只下载 99 张并生成一个有序清单。用模拟汇总验证了跨批图号和已完成批次复用。按每批单独向上取整，三批预留分别为 ¥9.12、¥9.12 和 ¥5.07。另计一次最终汇总 ¥1.42，共 ¥24.73。

正式实现需要在同一个作品内保存逐图结果和批次汇总的持久化检查点，将四次汇总纳入费用预览，并用真实高密度图文验证上下文长度与引用质量。当前线上导入能力仍适用常规张数上限。

### 预算页的收藏处理限制

在预算页的「收藏处理限制」可编辑图文常规上限和每日定时下载上限。初始值取部署配置，保存后使用同一工作流 SQLite 中的值。界面显示收藏调度时区下的日期、已用名额和保存后的剩余名额。调低下载上限后，同一天已占用名额的下载仍可继续，跨天续派按新一天的名额计算。设置为 0 可暂停派发新的定时下载，恢复时调回正数。

`PATCH /api/budget/favorites-limits` 使用登录会话、CSRF 校验及 `expected_revision`。图片上限至少为 1，下载名额可为 0。后台在派发事务中读取当前下载上限，图文报价和处理读取当前图片上限。保存只更新设置和变更历史。单篇例外仍需在收藏详情确认，项目预算和定时转换预算独立校验。

### 已取消图文的文本汇总恢复

任务已取消、最后的文本请求明确因输出长度截断、图文清单及逐图识别均完整可读时，任务页提供「仅重试文本汇总」。确认引用的是当前作品及当前费用上限。收费确认和原任务续跑入队在同一事务记录。后台校验相同的报价、图文清单和已保存证据，然后执行一次文本调用。追加预留计入项目预算。结果未明的请求保留账本记录，单次确认仅允许一次新请求。

文本汇总明确返回格式失败且逐图识别完整时，「需要关注」的任务也提供同一入口。历史错误 `invalid_summary_json` 可恢复。新的精简汇总将语法错误记为 `invalid_summary_json_syntax`（行、列），将字段错误记为 `invalid_summary_schema`（校验原因）。新的报价需要重新确认。

恢复使用配置项 `text_retry_prompt`，包含完整 JSON 示例及字段类型，把笔记限定为主题归纳和核心证据，完整逐图识别仍在结果中展示。上线时需将新版 `text_retry_prompt` 合入生产挂载的 `douyin-album.json`，沿用已有模型输出 Token 上限和费率。
