# 抖音收藏每日同步

## 规则

确认账号后建立最近 100 条收藏视频的基线。少于 100 条时须读到末页，正好读到 100 条时可完成基线。只保存作品 ID、标题及排序，下载和转换均为零。导入页可勾选标题或全选可导入项，确认下载权限后排队。历史回补只下载和入库，转换可在任务页另行启动。

每日按收藏顺序扫描，只有与上次快照衔接或确认读到末页时才登记新增。只把首个上次已知作品之前的未见作品判作新增。窗口后端补进的旧作品不进入队列。如果完整扫描后没有重叠，重新建立基线并提示，避免把旧收藏误当新增。识别不到账号、分页失败或没有读到边界时暂停派发。账号和队列分开保存，作品在资料库全局去重，包括回收站。只在账号核验通过后处理其队列。

每天默认最多下载 3 条、启动转换 3 条。按排队顺序续跑。自动下载和付费转换由服务器配置控制，自动转换开关默认关闭。已确认每日 ¥12.15、单条预留 ¥4.05，开启后仍受已有模型预算约束。转换生成待审核版本，由用户批准后进入增量索引。

如果旧作品未出现在前 100 条基线或后续扫描中，之后又被重新收藏到顶部，按新出现的收藏处理。作品库仍按 ID 去重。Cookie 更新后可在导入页点「读取收藏」，当天重新核验账号并恢复队列。

## 部署

将 `config/douyin-daily-sync.json` 复制到挂载配置目录，先只打开 `enabled`。新镜像包含 Playwright Chromium，默认使用随镜像安装的浏览器。先在导入页点击「读取收藏」并确认账号。确认基线数量和零派发后，再启用已有抖音下载配置，通过手选少量视频检查导入。

生产调度使用现有 worker，每天在配置的时区和时间首次检查时读取。默认候选为北京时间 05:30，晚于周日 03:30 的备份。启用时设置 `schedule_enabled`，确认自动处理授权后再设置 `auto_download` 和 `conversion_enabled` 及相应的日预算和单条预算。后台按 SQLite 中的日期记录去重，人工点击读取可以立即重试。

## 实施与验收

| 用例 | 预期 |
|---|---|
| FS01 | 新账号先显示待确认。确认后读取前 100 条并按顺序展示标题，零下载、零转换。读到不足 100 条且确认为末页也可完成。 |
| FS02 | 翻页中断保持原基线，账号不可确认或 Cookie 失效时暂停。刷新同一账号 Cookie 后沿用基线，切回已确认账号后续跑原队列。 |
| FS03 | 新增 5 条且每日上限 3 条，首次派发 3 条，其余 2 条次日续跑。窗口末尾滑入的第 101 条旧收藏不会排队。 |
| FS04 | 逐项勾选、全选和取消全选。提交后以当时选择排队，重复提交、跨账号重复和回收站作品均不会生成重复导入。 |
| FS05 | 同日重复触发或任务中断恢复不重复排队。预算不足暂停转换，未授权时历史回补只下载入库。 |
| FS06 | 实际定时触发一轮，少量新增可进入待审核，经本人批准后增量索引。核对服务器日志、每日上限及 Cookie 失效恢复。 |

本地以模拟账户和作品数据覆盖 FS01–FS05。浏览器联调核对了确认账号、100 个标题、基线零派发、全选和确认下载权限后入队。本机真实账号只读获取到前 100 条收藏，17 次收藏请求均返回 HTTP 200。部署后用生产账号核对只读基线，再启用生产调度并验收 FS06。
