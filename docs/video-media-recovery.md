# 视频无语音与媒体缓存恢复

## 处理规则

- 无音轨时直接执行画面分析和摘要，跳过语音请求与预留。转录服务明确返回无有效语音或无可识别词时，保存已完成的语音结果，继续画面分析。网络、格式及其他识别错误仍按各自状态处理。
- 视频时长按容器显示，抽帧使用实际画面轨范围。音频按可用音轨提取。新缓存完成后再发布清单，已完成的旧缓存继续校验原指纹和素材摘要。
- 待审核版本保留来源原文、画面及时间证据。详情说明无音轨、未检测到语音或经确认按画面继续。人工补写转录后，进入正常转录展示。

## 旧任务处置

- 已持久化终态语音失败且没有后续模型阶段的任务，可选择「仅按画面和原文继续」。用户同意处理费用后复用旧任务及素材，保留供应商结果和预留，不再次提交语音请求。无法获取旧供应商细因时，页面显示已知的失败阶段和处理选择。
- 旧缓存缺少完成清单，且任务未开始任何外部步骤时，可选择「重建缓存并重试」。保留旧缓存和尝试记录，单独记录恢复操作。中断后可继续已经授权的重建流程，预算校验仍适用。
- 接口 `POST /api/tasks/{id}/visual-only` 与 `POST /api/tasks/{id}/rebuild-media` 沿用会话和 CSRF 校验，并要求 `allow_paid: true`。同一操作已排队时重复提交返回现有状态。常规重试上限仍生效。

## 测试用例

| 用例 | 验收 |
| --- | --- |
| VM01 | 纯音乐或服务明确返回无可识别片段时生成视觉证据和待审核版本。正常语音、临时失败及旧模型中断续跑继续沿用原行为。 |
| VM02 | 无音轨时没有语音请求及对应预留。人工补写转录后，历史版本仍保留原状态。 |
| VM03 | 音轨和画面轨长度不一致、很短的视频及旧完整缓存均可按真实范围取帧。失败的暂存文件不污染正式缓存。 |
| VM04 | 终态语音失败保留历史与预留。默认恢复被拦截，明确同意后仅续跑画面和摘要，重复提交不新增请求。 |
| VM05 | 达到常规上限的旧部分缓存可重建，原片、缓存和尝试记录保留。进程中断后通过已保存的恢复状态继续。 |
| VM06 | 在桌面和手机查看失败摘要、详情及费用提示。点击允许的操作后进入排队，刷新不重复提交。 |
