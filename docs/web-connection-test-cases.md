# 本机网页启动验收用例

1. 使用验收副本配置启动：返回健康状态及 PID，退出启动器后服务持续响应。
2. 再次启动：识别已有本应用，报告状态，不启动或终止进程。
3. 端口被其他服务占用：明确报错，不终止占用进程。
4. 非回环地址、无效配置、不可用 Python：拒绝启动并提示。
5. 路径含空格：配置路径完整传递；启动失败时给出日志路径。
6. 默认 config/web.json 为正式配置；验收时显式指定副本，不修改原数据或读取真实环境文件。
7. 已完成HTML任务没有数值进度时显示“处理完成”，不能继续显示“处理中”。

## 2026-11-05 实测结果

- 验收副本启动后 `/api/session` 返回 200，启动器退出后仍可访问；重复执行识别 PID 18016。
- 指定正式配置而端口由验收副本占用时，报告配置不一致。
- `0.0.0.0` 配置被拒绝；不存在的 Python 路径启动失败。
- 临时 TCP 服务占用端口时报告无法验证，检查确认该服务仍在监听，随后按测试程序自身超时退出。
- 临时配置及服务日志位于 `tmp/web-server/`。含空格路径及启动超时场景尚未实测。

## Windows 启动路径与超时补验

| 编号 | 场景 | 验收标准 |
|---|---|---|
| WS01 | 使用含空格的绝对或相对配置路径启动隔离服务，并以同一配置再次启动 | 完整配置路径正确传给 Python。服务返回真实会话健康响应，重复启动识别同一配置和 PID。 |
| WS02 | 模拟所启动的进程迟迟不健康或提前退出 | 在预期时限内给出失败及日志位置，失败后不留下本次创建的服务进程或无效 PID 记录，可用同端口重试。 |
| WS03 | 端口已有无关服务，或被其他服务抢先绑定 | 启动器不认领或停止已有服务，并报告占用或启动失败。 |
| WS04 | Windows 本机开启登录认证，从未登录状态首次启动，再以同配置启动 | 公开健康端点正常时启动成功，未经认证的会话端点仍返回 401。重复启动识别相同 PID，服务保持运行。 |

2026-11-10 Windows PowerShell 5.1 与 PowerShell 7 隔离验收均通过。WS01 使用真实 Uvicorn 和项目内含空格的绝对及相对配置路径，重复启动确认相同 PID。WS02 模拟慢启动和提前退出，报错带日志位置，本次失败进程退出且未写 PID，同一端口随后启动成功。WS03 模拟预先占用与启动后抢占，两个无关监听均持续响应。WS04 启用登录认证后，未登录的会话请求继续返回 401，首次与重复启动均确认同一 PID。

健康检查间隔、启动等待、单次 HTTP 探测及清理等待参数见 [web-launcher.json](../config/web-launcher.json)。默认启动等待从创建子进程起算，设为 10 秒。单次 HTTP 探测按秒计，启动器另有环境预检和失败清理耗时。
