## 实现约定

### Git 工作树一键部署验收用例

| 编号 | 场景 | 通过条件 |
|---|---|---|
| OD01 | 首次部署已准备好的服务器 | 预检通过后构建候选镜像，启动指定项目 Web/worker，检查运行镜像与回环、HTTPS 健康 |
| OD02 | 从 Git 更新已有安装 | 复用外部配置、秘密、工作流和预算账本，核对已运行服务挂载，保存旧镜像标签后切换 |
| OD03 | 预检或候选构建失败 | 在修改运行镜像之前停止，既有容器继续服务 |
| OD04 | 切换或健康检查失败 | 已有运行中的安装恢复旧镜像并复查健康，首次部署清理本次失败的项目容器，保留外部数据并返回失败结果 |
| OD05 | 检查模式、错误挂载和并发 | 检查模式可先核对安装，挂载不匹配、状态异常或已有部署在运行时拒绝切换 |
| OD06 | 空安装首装、失败重试与未计费升级 | 检查模式保持只读。实际首装初始化工作流库与空预算账本，成功后无需先调用模型即可升级，首次切换失败后也可重试。初始化部分失败只清理本次新建文件，迁移缺库时拒绝补写 |
| OD07 | 两个旧服务均停止时切换失败 | 恢复旧镜像引用，两个容器继续处于停止状态，并核对容器状态和镜像 ID |
| OD08 | 切换期间收到 SIGHUP 或 SIGTERM | 进入回滚并验证先前运行或停止状态，回滚结束后恢复原信号处理器 |

### 2026-11-06 首次云端构建失败修复用例（实施前）

- BF01：按Dockerfile前端阶段的实际WORKDIR/COPY布局隔离构建；`web/src`引用的`../../config/*.json`全部可解析，Vite产物存在于最终阶段COPY源路径。旧布局应复现缺失配置，修复布局应构建成功。
- BF02：部署回归与现有前端用例通过；新部署包ZIP CRC、内部逐文件SHA及包SHA校验通过，不包含秘密/业务数据/node_modules。
- BF03：服务器将更新包解压到独立代码目录，沿用同级既有config/state/secrets/backups；实际镜像构建成功、记录镜像ID与磁盘余量后才进入恢复，不将本机模拟视为Linux镜像验收。

### 2026-11-06 Docker内国内Debian源用例（实施前）

- BF04：解析外部DEB822配置，主仓库/安全更新均使用国内HTTPS镜像，固定bookworm/bookworm-updates/bookworm-security，保留Debian官方Signed-By；不禁用TLS或包签名。
- BF05：仅在本项目Dockerfile的Python阶段apt update之前复制源配置；部署包包含该文件，前端目录修复/部署回归保持；不改宿主机源、Docker daemon、Compose项目或其他应用。
- BF06：新包CRC/内部SHA与包SHA通过；服务器独立app-buildfix2构建使用已有config/state/secrets/backups、缓存和独立personalkb项目，记录实际下载/镜像/磁盘；慢速构建先由本人Ctrl+C停止，不停止其他容器，不做全局清理。

### 2026-11-07 后续构建pip国内源用例（实施前）

- BF07：解析项目外置pip-build.conf，索引为国内HTTPS单一源，保留TLS，不配置trusted-host或额外索引；同一RUN的三个pip install均使用此配置，保留版本及no-deps约束。
- BF08：PIP_CONFIG_FILE仅在安装RUN导出，不写ENV、不修改主机/运行时pip默认配置；白名单包包含配置并通过SHA/清单校验，部署及前端回归保持。
- BF09：本次服务器buildfix2已BUILD_OK，继续沿用该镜像/app-buildfix2进行迁移，不要求为后续下载优化再次重建；先独立restored验证完整性与来源4/版本6/审核5/任务4及预算账本，目标生产库不得覆盖。

### 2026-11-07 生产RAG状态503修复用例（实施前）

- RP01：在Linux/POSIX语义下，configure生成的绝对秘密路径及/state预算账本能被RAG配置加载；原开发相对路径兼容。
- RP02：只允许受信任配置的env_file及budget.ledger使用本地绝对路径，index_dir/models_file仍受相对路径边界限制，越界/非法路径拒绝；不把账本改回/app或新建空账本。
- RP03：迁移后只读状态返回需要重建而非503；不调用模型、不重评、不改预算，不因检查触发索引构建。
- RP04：使用现有personalkb镜像为基础，只COPY修复代码生成新镜像，离线验证生产配置；保留原镜像与生产数据，通过后仅重建本项目web/worker，无依赖重装或全局Docker操作。

- 生产使用现有Nginx→主机回环端口；Compose在Linux使用host网络，Web只监听127.0.0.1，独立worker不监听端口。避免新增代理抢占80/443。现有本机8765实例不在本轮自动切换生产认证。
- 代码/app只读，配置/app/config只读，秘密独立挂载/run/secrets/personalkb.env；持久根/state下workflow及budget.sqlite，临时/app/tmp独立持久工作目录；备份根/backups不得位于数据子树。
- Web/worker分别持有生命周期文件锁，维护同时取得两把锁及既有执行锁。只在停止自有服务的维护窗口备份/清理，不声称跨文件/多数据库在线原子快照。
- 备份按内容哈希复用对象，快照保留7代；人工下载独立转移包和可配置私有OSS推送均需校验。本轮没有授权替用户购买存储或对外上传。
- 已确认的临时ASR传输继续默认，正式OSS音频模式仍由本人手动启用，不能与备份OSS配置混淆。
