# Phase 3正式RAG编码前验收用例

日期：2026-11-05；PRD v0.17。用户已授权Phase 3。用例先于任何新增业务代码，实施依据[契约](phase-3-rag-contract.md)。真实现有业务内容仍待本人评分，不移植预研批准，不替本人审核。自动化只在独立库使用明确synthetic评分/假向量/假回答；真实模型调用/质量另记。

| 编号 | 场景 | 验收标准 |
|---|---|---|
| R01 | 正式资格入口 | 必须启用content_storage；只取当前版本最新approve≥98且文件/附件校验与同步通过的来源，排除草稿/低分/拒绝/撤回/删除/损坏 |
| R02 | 索引构建资格竞态 | embedding期间编辑/撤审/删除/损坏任一来源，发布前复验，不能把旧快照发布成有效索引；外部调用不持SQLite长事务 |
| R03 | 原始证据分块 | HTML body/evidence、视频audio/visual证据优先，1000字符/120重叠及标题边界；摘要仅导航，不能当原文证明；无定位视频明确排除或标不可引用 |
| R04 | 分块身份与定位 | chunk绑定source/version/content SHA/证据身份/space；摘录精确等于原证据字符范围；音频真起止时间、视觉真时间点/帧SHA，HTML不可伪称DOM定位 |
| R05 | FTS/向量混合召回 | sqlite-vec0.1.9、text-embedding-v4/1024、中文双字/英文数字FTS、双路Top10/RRF60/默认回答5块；向量有限非零float32、数量/维度/顺序严格校验 |
| R06 | 过滤先于排名截断 | 来源/主题/标签范围，维度间AND同维多选OR；构造全局TopK全为范围外的对抗例，范围内正确证据仍可召回；别名/目录改名不改变稳定ID |
| R07 | 空库/无答案/低依据 | 无合格资料不调用模型、返回明确无依据；模型拒答不展示无关候选引用；不把向量相似性本身解释成事实支持 |
| R08 | 空间隔离 | 模型名/显式版本/维度/分块或tokenizer变化不混搜，旧索引明确需重建；固定别名不是不可变权重保证，配置指纹及返回模型可追溯 |
| R09 | 原子重建/重启/缓存 | staging构建、ready后原子切换；失败/中断不破坏旧active；仅合格同空间内容允许复用向量，重启不采用未完成库；更新/删除同步清理正文FTS/vec |
| R10 | 编辑/重传后失效 | 正文版本变化、新版本待审时旧索引立即不能命中；重新批准/重建后只用当前版本，无静默继承旧评分 |
| R11 | 撤回/删除/文件损坏 | 词法/向量/混合及旧chunk引用入口均不返回失效内容；物理清理由同步或查询前维护完成，不允许清理前的逻辑泄漏；不得自动reconcile修复损坏后继续答 |
| R12 | 生成间状态变化 | 检索后、模型开始前、模型返回后、输出前复验所有上下文（含模型未引用项）；任一失效丢弃整答，不透传生成中的事实token |
| R13 | 引用约束 | 模型引用只能来自本次有效上下文，正文ID集合与citation_ids一致；未知ID/伪造摘录/缺引用/不一致拒绝；客户端只显示结构化引用、不执行模型HTML |
| R14 | 引用打开/定位 | 打开引用再次校验资格/space/version/SHA；有效片段显示原文与已有时间，失效明确409/410并不回传旧原文；引用与检索候选不混淆 |
| R15 | 受控服务与费用 | embedding/answer独立配置，复用两Key；明确allow_paid、输入/输出限额、价格日期、保守预留及共享100元研究预算；已知usage结算、未知保留，无自动POST重试 |
| R16 | 持久请求与幂等 | request_id输入/配置指纹绑定；同ID不同payload冲突；未决请求恢复needs_attention，不重复收费；缓存答案仍须当前资格复验 |
| R17 | 安全事件流 | 仅进度可先发送；完整结构化回答校验后再answer事件，期间撤审无正文泄漏；结束前再校验，失效客户端清除结果，断线不自动重发收费POST |
| R18 | 单worker/资源与API | build/付费生成遵守execution_guard，busy无外部调用；索引/status/只读引用不触发付费；会话/CSRF及安全码，模型内容视为不可信数据 |
| R19 | Web端到端 | 索引状态/明确构建、范围检索/问答、进度/拒答、引用定位、更新失效及错误可操作；隔离假模型点验，不改真实评分或付费 |
| R20 | 回归与交付 | 新用例及既有后端/独立依赖/前端/构建/独立Review通过；真实资料只读清单不变；文档区分工程验收、真实回答评分及目标Linux性能，Phase 4未开始 |
| R21 | 人工修订证据闭环 | 修正文/转录/视觉→新版本待审→本人批准（测试仅synthetic）→重建后检索修正文本，不继续把旧错误当新版证据；旧原始证据留父版本，笔记/摘要改动不伪造源证据；无明确时间的人工文本可引用版本字符范围但必须明确无视频时间，不继承旧时间/帧SHA |

本轮不重复已通过抖音下载，不以预研approved bundle自动写正式库；不静默切词法替代失败向量模式，不使用另一个更便宜模型自动替换已选基线。Git commit/push/tag依旧需确认。

## 索引代回收

| 编号 | 场景 | 通过条件 |
|---|---|---|
| RG01 | 重建成功、失败及并发读者 | 成功切换后回收废弃生成文件。失败或读者仍占用时保留原活动库，重试后正常切换。索引状态与词法检索在混合检索调用模型期间仍可读取 |
| RG02 | 冷备自定义索引目录及旧代 | 识别活动代后仅备份活动索引，合并其 SQLite WAL 或 journal 状态。无法确认活动代时保守保留库文件。既有快照按原规则轮换 |
| RC02 | 发布锁在建索引前已被读者占用 | 返回忙碌时模型调用数为零，释放锁后可重建。付费重建持有索引锁，读请求可能超时并提示重试 |
| RC03 | 活动清单缺字段，或已识别活动库损坏 | 缺字段时保守保留生成文件。活动库 SQLite 完整性校验失败时保留上一份可用快照 |
