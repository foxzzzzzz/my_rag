# 回答按文章分段：编码前用例

日期：2026-11-06；用户要求已生成问答有效分段，提高阅读性。先按以下用例实施，只增加显示层段落，不改措辞、原answer、证据和已批准评分绑定，不调用模型。

| 编号 | 场景 | 验收标准 |
|---|---|---|
| P01 | 语义与原文 | 按句末、话题转换和较长并列分句分段，不按固定字数截断；返回原文连续切片，连接后逐字等于原answer，不增删标题、结论、措辞 |
| P02 | 引用归属 | 句末后的连续引用留在所属句段，引用不可被切开或单独悬成一段；跨段编号仍按全文首次出现，重复编号不重置 |
| P03 | 保护技术文本 | 引号、行内/围栏代码中的标点不误分；路径、数字小数、普通方括号保持完整；保留原有有效换行，拒答/短答不强制分段 |
| P04 | 两端一致 | 静态评分页与正式React页共用config/answer-layout.json规则，同一组输入生成相同段落切片；参数外置解释，超长无安全分隔点时保持完整 |
| P05 | 阅读版式 | 正文用实际段落元素与适当段距/行高，已有①引用和来源卡交互正常，390px无溢出；默认不新增HTML/脚本解释 |
| P06 | 回归与发布 | 9题原输出SHA/评分/备注保留，刷新草稿与真实JSON导出仍有效；相关测试、构建及独立Review通过，合并发布不清除评分页，更新PRD/PLAN/Todo/CHANGELOG和验证记录 |

对于当前Q01–Q07长回答应出现自然段；Q08/Q09短拒答保持单段。布局规则不保证理解所有文体，缺少安全边界时优先保留原文，不强行切词。后续若需模型直接输出结构化文章，应另行验证，不在本次重生成已评分结果。
