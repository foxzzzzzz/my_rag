# 历史版本保留与清理验收

同一条资料每次保存都会产生完整快照。2026-11-17 的生产库只读预演覆盖 23 条在库资料和 32 个版本。只有一条资料超限，两个候选版本合计约 202 KiB 内容，引用的关键帧均仍在使用。

`maintenance.json` 的 `version_history_retention` 控制定期冷备后的历史清理。默认保留当前版、最新审核为批准且达标的一份历史版，以及剩余历史中最新的一份。没有批准旧版时最多两份。相同创建时间按数据库插入顺序排序。既有挂载配置未包含该段时维持关闭。普通备份保留原行为。

维护锁覆盖冷备的校验、发布和清理。SQLite 保存清理标记和待删文件，历史元数据和审核继续可读。文件清理前更新内容清单，只有保留版本均未引用的知识库关键帧才可删除。知识文件已不一致的资料在报告中标明跳过原因。删除的对象限于版本正文、版本证据和独占知识库关键帧。原件、临时处理缓存、审核以及冷备仍遵循各自的保留规则。

| 用例 | 通过条件 |
|------|----------|
| VR01 保留规则 | 旧版最后一次审核为返工时，不占批准名额。当前版、最新达标批准旧版和最新其他旧版各保留一份。没有批准旧版时保留两份。 |
| VR02 元数据与审核 | 旧版正文清空，原 ID、标题、时间、类型、父版本、哈希及审核仍可读。Web 标记清理，旧版正文、下载和画面入口隐藏。 |
| VR03 文件与检索 | 删除旧版 Markdown、证据和独占帧。共享帧、当前内容校验及已批准资料的检索资格保持。 |
| VR04 冷备门槛 | 冷备校验失败时不清理。普通备份不触发清理。发布的清理前快照可恢复完整旧版及附件。 |
| VR05 中断重试 | 清理前持久化快照 ID。即使只保留一份快照，连续失败、普通冷备和成功重试期间仍可恢复最初快照。成功重试只继续已标记的清理，随后恢复正常轮换。 |
| VR06 定时入口 | 启用后走联合冷备清理命令。失败报告保留原因，旧配置继续沿用原流程。 |
